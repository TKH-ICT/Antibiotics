## 1. 背景と課題

現行の抗菌薬投与マニュアルはPDF（77ページ）で配布されている。内容は院内コンセンサスとして質が高い一方、
臨床現場での利用には以下の摩擦がある。

| 課題 | 具体例 |
| --- | --- |
| 目的の情報に到達するのが遅い | 「セフェピムの腎機能低下時の量」を知るのに、目次 → p.16 の表 → 該当行、と3ホップ必要 |
| 情報が薬剤単位で分散 | 1剤の情報が「成人静注(p.10)」「腎障害時(p.16)」「透析(p.21)」「CHDF(p.22)」「小児(p.38)」「適応外(p.52)」「採用薬一覧(p.65)」の7箇所に散在 |
| 成人・小児の取り違えリスク | 同じPDF内で章が違うだけ。スクロール中に混線しうる |
| 計算が手作業 | CCr（Cockcroft-Gault）、体重あたり用量、理想体重／補正体重を毎回電卓で計算 |
| 適応外使用が引けない | p.52-56は薬剤名の箇条書きのみ。「壊死性筋膜炎で適応外使用が認められている薬は？」と疾患側から引けない |
| アンチバイオグラムが読みにくい | 横長の感受性率表。菌名は学名のみで、「腸球菌」「緑膿菌」など日本語からは引けない |

## 2. コンセプト

> **「薬剤名 or 菌名を打てば、その患者に投与できる量が3タップ以内で出る」**

紙のマニュアルを電子化するのではなく、**マニュアルの情報を「患者条件（成人/小児・腎機能・体重）で解決済みの答え」に変換して提示する**アプリ。

### 設計の3原則

1. **入口は原典の章立てに合わせ、患者集団は必要な階層で分ける** — オープニング画面の大項目
   「内服薬／注射薬／感染症別／菌種別／その他」から選ぶ。成人／小児は**内服薬・注射薬・感染症別を選んだ直後**に毎回選ぶ。
   菌種別（菌側の感受性率）は患者集団に依存しないため、集団を選ばせずに直接開ける。
   薬剤に入った後は**選択中の集団の用量しか画面に出さない**（誤参照の構造的防止）。
   小児では、成人向けの情報（腎機能低下時の投与量表など）自体を表示しない。
2. **1薬剤 = 1ページに集約** — 原典で7箇所に散っている情報を、薬剤詳細画面に「通常量／腎機能／透析・CHDF／TDM／適応外／製剤情報」のセクションとして縦に並べる。
3. **計算はアプリがやる** — 体重・年齢・Cr・性別を一度入れれば、CCr、eGFR区分、mg/kg換算、理想体重・補正体重を自動計算し、該当する用量行をハイライトする。

#### 補足: 成人・小児の取り違え防止をどう担保するか

版0.1 の「片方の集団の用量しか画面に出さない」という構造的な防止は**そのまま維持する**。
変わるのは適用範囲だけで、アプリ全体のモードだった集団選択を、
**実際に用量を左右する薬剤の画面の中に閉じ込める**。菌種別には波及させない。
さらに、小児では成人向けの腎機能低下時の投与量表を画面から取り除く（見えていること自体を誤参照の元とみなす）。

小児は体重未入力なら mg/kg 表記のみとし絶対量を出さない、原典に記載のない小児量は推定しない、
という安全要件も引き続き必須とする。年齢からの成人／小児の自動判定は行わない
（原典に閾値の記載がなく、アプリが独自の境界を持ち込むことになるため）。

## 3. 想定ユーザーと利用シーン

| ユーザー | 主な利用シーン | 求める速度 |
| --- | --- | --- |
| 研修医・若手医師 | 病棟・ER で処方オーダー直前に用量確認 | 10秒以内 |
| 指導医・専門医 | 適応外使用の可否確認、TDM 方針決定 | 30秒以内 |
| 病棟薬剤師・薬剤部 | 疑義照会、TDM 投与設計、腎機能に応じた減量提案 | 1分以内（設計計算含む） |
| 看護師 | 投与時間・溶解方法・配合変化の確認 | 10秒以内 |
| ICT / AST | 適正使用の教育・監査、アンチバイオグラム参照 | — |

主戦場は **スマートフォン片手・立ったまま・院内Wi-Fiが弱い場所**。→ オフライン動作は必須要件。

## 4. 提供価値（ご要望との対応）

| ご要望 | アプリでの実現 |
| --- | --- |
| 抗菌薬名で検索し通常量がすぐ示される | インクリメンタル検索（一般名／商品名／略語／カナ／英名）。検索結果カードに通常量を直接表示し、開かずに読める |
| 腎機能低下時の投与量がすぐわかる | 薬剤詳細に腎機能セクションを常設。腎機能を入力済みなら該当区分を自動ハイライト、未入力ならCCr>50 / 10-50 / <10 / HD / CHDF を並べて提示 |
| 成人と小児を取り違えない | 内服薬・注射薬を選んだ後に集団を選び、以降は選択中の集団の用量のみを表示。小児は体重未入力なら mg/kg 表記のみ（版0.2で選択の位置を起動時から薬剤レーン内へ移動） |
| 剤形から入って絞り込める | 内服薬／注射薬を入口で分け、内服はAWaRe分類（Access/Watch/Reserve）の大ボタン、注射は系統から選ぶ。理由がなければAccessから選ぶことを画面上で強調する |
| 投与設計（VCM等） | TDM設計ツールを独立機能化。VCM（トラフ／AUC）、TEIC、GM/AMK（MDD/ODD/心内膜炎併用）、VRCZ に対応 |
| 適応外使用を薬剤名・疾患名の双方から検索 | 適応外使用を「薬剤 × 疾患 × 用法用量 × 区分」の関係データとして持ち、双方向インデックスを張る |
| 菌名検索とアンチバイオグラム（学名・日本語名など複数表記） | 菌マスタに 学名／日本語名／略号／通称／よくある綴り違い を別名として登録。菌詳細で入院・外来のアンチバイオグラムをヒートマップ表示 |

## 5. 機能スコープ（フェーズ分割）

### Phase 0 — MVP（原典の中核を引ける）
- 成人／小児モード切替
- 薬剤検索・薬剤詳細（通常量・腎機能・透析・CHDF）
- 患者条件パネル（年齢・性別・体重・身長・Cr → CCr/eGFR自動計算）
- 菌名検索＋アンチバイオグラム（入院／外来）
- 適応外使用の双方向検索
- オフライン動作（PWA）、免責表示、データ版表示

### Phase 1 — 投与設計と周辺章
- TDM 投与設計（VCM トラフ／AUC、TEIC、AG、VRCZ）
- 周術期予防抗菌薬（術式領域 → 推奨薬 → 1回量・再投与間隔）
- 採用注射薬一覧（規格・薬価・投与時間・筋注可否・申請書要否・配合変化）
- 申請制抗菌薬のフラグ表示、AWaRe分類バッジ
- ペニシリンG持続静注の調製手順

### Phase 2 — 運用・拡張（実装済み）
- 曝露後予防投与のクイックリファレンス（アナフィラキシー対応は Phase 3 で削除）
- 抗菌薬適正使用指針、AMR対策の読み物セクション
- 検索ログの匿名集計（どの薬・菌がよく引かれるか → ICT/ASTの教育に活用）
- 年次改訂ワークフロー（データのみ差し替えて配信）

### Phase 3 — UI再編（実装済み）

原典の章立てに沿った導線へ作り替える。データ・臨床コンテンツには手を触れず、UI層のみを対象とする。
詳細は [docs/06_UI再編計画.md](06_UI再編計画.md)。

- オープニング画面（タイトル・イラスト・大項目5ボタン）を設ける
- 大項目は「内服薬／注射薬／感染症別／菌種別／その他」。「その他」は 周術期／暴露後予防投与／小児体重服用量簡易表／AMR対策
- 成人／小児は内服薬・注射薬・感染症別を選んだ直後に毎回選ぶ。菌種別では選ばせない
- 感染症別は厚生労働省『抗微生物薬適正使用の手引き 第四版』から一部採用し、急性下痢症と院内発症感染症に限定する
- 小児では成人向けの情報（腎機能低下時の投与量表など）を表示しない
- 投与設計・ペニシリンG持続静注・採用薬一覧は各薬剤の説明ページに紐づける
- アナフィラキシー対応の項目を削除
- 内服薬レーンに AWaRe分類による絞り込みを新設（原典 p.74 は内服薬のみを対象とするため注射薬には置かない）
- **TDM画面の不具合是正** — 患者条件が未入力だと初回投与量が表示されない（VCM）、
  逆に腎機能正常時の用量が既定値として出る（アミノグリコシド）等、薬剤ごとに異なる欠測時の挙動を統一し、
  初回投与量と採血タイミングを常に確実に提示する
- 表組みの列幅・折り返しを是正し、狭幅画面ではカード表示へ落とす

### Phase 4 — 実測値によるTDM投与設計（見送り）

血中濃度の実測値と投与時刻から個別の薬物動態パラメータを推定し、投与計画を計算する構想。
技術的には確立した手法（Sawchuk-Zaske法ほか）で実装可能だが、
**「マニュアルの閲覧支援」から「投与設計の支援」へアプリの位置づけが変わる**ため、
§7 のSaMD該当性の再確認と薬剤部（TDM担当者）の監修が前提となる。

**2026-08-27 の判断で見送りとした。** アプリは引き続き「原典に記載された表・式のみを実装し、
独自の薬物動態推定は行わない」方針を維持する。検討の記録（手法・前提条件・リスク・段階分け）は
[docs/06_UI再編計画.md §3.3](06_UI再編計画.md) に残してある。

## 6. 技術方針（案）

| 項目 | 方針 | 理由 |
| --- | --- | --- |
| 形態 | PWA（インストール可能なWebアプリ） | iOS/Android/PC を1コードで賄える。院内配布が容易（URL共有）。将来 Capacitor でストア配信も可 |
| 実装 | TypeScript + React + Vite | 型でデータ構造の破綻を防ぐ。医薬品データは型定義との整合をCIで検証 |
| データ | コードと分離した JSON（+ JSON Schema 検証） | 年1回の改訂をエンジニア無しでも差し替えられるようにする |
| 検索 | クライアント内の全文検索（Fuse.js 等） | オフライン必須。データ量は数百件で十分に軽い |
| 通信 | 原則なし（完全クライアント完結） | **患者の体重・Cr等をサーバへ送らない** = 個人情報の域外流出リスクをゼロにする |
| 配信 | Cloudflare Pages で一般公開（2026-08-27 一般公開を決定、2026-09-11 に GitHub Pages から移行） | 院内サーバの構築・維持が不要で、URL共有だけで配布できる。患者条件は端末内のみで計算し送信しないため（NFR-006）公開範囲を広げても情報漏えいリスクは生じない。院内固有の情報（適応外使用・採用薬・アンチバイオグラム等）は、初回起動時の確認・全画面フッタ・「アプリの説明」で適用範囲を明示することで担保する（FR-012） |

## 7. リスクと対応

| リスク | 対応 |
| --- | --- |
| **薬機法上の位置づけ** — 用量計算機能はプログラム医療機器（SaMD）該当性の検討が要る | 「院内マニュアルの電子的閲覧支援」に留め、診断・治療方針の提示は行わない。計算は原典に明記された式（Cockcroft-Gault、理想体重、mg/kg）の実行のみとし、根拠となる原典ページを併記する。公開前に薬剤部・法務で該当性を確認 |
| **データ入力ミスが患者に直結** | 全データに原典ページ番号を必須項目として持たせ、画面から辿れるようにする。二重入力＋薬剤部によるダブルチェックを工程に組み込む。CI で JSON Schema 検証 |
| **改訂版とのズレ** | アプリ内に常時「データ版：第9版（2026-04-01）」を表示。改訂時はデータJSONのみ差し替え。旧版キャッシュ利用時は警告 |
| **免責の周知不足** | 初回起動時に免責同意、各用量表示に「添付文書・原典の確認」注意書きを常設 |
| 原典PDFの表がテキスト抽出で崩れる（特にアンチバイオグラム） | アンチバイオグラムは PDF ではなく**作成元のExcelから取り込む**。他の表は手入力＋校正 |
